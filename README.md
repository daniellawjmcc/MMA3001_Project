
# Deep Learning for Pork Packaging Defect Detection

A comparative evaluation of YOLOv8n, RetinaNet ResNet50-FPN V2 and Faster R-CNN ResNet50-FPN V2 for automated pork rasher packaging defect detection.

This repository contains the data-processing utilities, model evaluation notebooks, training reproduction scripts, unit tests and project documentation developed for the MMA3001 project.

## 1. Project Overview

The project investigates deep learning-based object detection for identifying packaging defects in pork rasher images.

The original experiments included five defect categories. The final experiments focused on four:

- `loose-meat`
- `packaging-error`
- `twisted-meat`
- `unsealed`

The fifth class, `wrinkle`, was excluded from the final model comparison because it had limited independent source-image representation.

Three object detection architectures were evaluated:

1. YOLOv8n
2. RetinaNet ResNet50-FPN V2
3. Faster R-CNN ResNet50-FPN V2

The comparison considers detection accuracy, class-specific performance, confidence-threshold selection, generalisation and computational requirements.

## 2. Main Results

The final comparison was performed using a common COCO-style evaluator in Notebook 07.

| Model | Validation mAP@50:95 | Held-Out Test mAP@50:95 |
|---|---:|---:|
| YOLOv8n | 0.3278 | **0.2698** |
| RetinaNet | 0.2465 | 0.1494 |
| Faster R-CNN | 0.3222 | 0.1482 |

YOLOv8n achieved the highest test mAP@50:95 and the smallest validation-to-test performance decrease.

The four-class validation and test splits contain 120 and 80 images, respectively.

### Final Confidence Thresholds

Confidence thresholds were selected using validation Macro-F1 and frozen before test evaluation.

| Model | Selected Threshold |
|---|---:|
| YOLOv8n | 0.200 |
| RetinaNet | 0.200 |
| Faster R-CNN | 0.500 |

These values are from the common-evaluator model comparison. Native YOLO validation results may differ because the evaluation settings are not identical.

## 4. Installation

### Requirements

Python 3.11 or later, with compatible PyTorch and Torchvision versions.

Clone the repository:

```bash
git clone <YOUR_GITHUB_REPOSITORY_URL>
cd MMA3001_Project
```

Install the dependencies:

```bash
python -m pip install -r requirements.txt
```

On Windows PowerShell, make the package importable:

```powershell
$env:PYTHONPATH = "src"
```

On Linux or Google Colab:

```bash
export PYTHONPATH=src
```

The notebooks also configure the shared module path in their Google Colab setup cells.

## 5. Dataset Organisation

The original data is stored outside the Git repository.

The training and evaluation scripts expect an external project-data directory similar to:

```text
MMA3001_Project/
├── dataset/
│   ├── pork_rasher_v4/
│   ├── pork_rasher_v4_clean/
│   └── pork_rasher_v4_4class/
└── model_runs/
```

The five-class cleaned dataset is:

`dataset/pork_rasher_v4_clean/`

The final four-class dataset is:

`dataset/pork_rasher_v4_4class/`

Each dataset uses the YOLO object detection structure:

```text
dataset_name/
├── train/
│   ├── images/
│   └── labels/
├── valid/
│   ├── images/
│   └── labels/
├── test/
│   ├── images/
│   └── labels/
└── data.yaml
```

The `mma3001.dataset` module reads and validates annotations, converts normalised YOLO bounding boxes into pixel coordinates, and supports both zero-based and one-based class-label conventions.

## 6. Dataset Preparation

Dataset construction is implemented in:

`src/mma3001/prepare_dataset.py`

This is separate from `dataset.py`, which only loads and validates data.

The preparation module provides source-level wrinkle split cleaning and four-class filtering.

Run the following commands from the repository root after installing dependencies and setting `PYTHONPATH=src`.

### Create the cleaned five-class dataset

```bash
python -m mma3001.prepare_dataset --stage clean-five --project-root /content/gdrive_new/MyDrive/MMA3001_Project
```

### Create the final four-class dataset

```bash
python -m mma3001.prepare_dataset --stage make-four --project-root /content/gdrive_new/MyDrive/MMA3001_Project
```

### Run both preparation stages

```bash
python -m mma3001.prepare_dataset --stage all --project-root /content/gdrive_new/MyDrive/MMA3001_Project
```

These commands are intended for a fresh data-preparation workspace. Existing prepared datasets are protected against overwriting.

The preparation implementation has not been validated through a complete fresh reconstruction of the original datasets. Dataset counts and annotations should be checked before treating reproduced copies as equivalent to the originals.

### Reproduction Notes

New checkpoints are written to `reproduction_*` directories instead of the original run directories.

Training results are not guaranteed to be bit-for-bit identical because of random operations, software versions and hardware differences.

The standalone training scripts have not been verified by rerunning all training epochs.

## 10. Evaluation Methodology

The project uses the following detection metrics:

- mAP@50
- mAP@50:95
- Per-class average precision
- Precision and recall
- Micro-F1 and Macro-F1
- TP, FP and FN counts
- Raw and normalised confusion matrices
- Inference latency and throughput

Fixed-threshold detection matching uses IoU = 0.50.

COCO-style mAP and fixed-threshold F1 are separate metrics and should not be interpreted as equivalent.

Validation data is used for operating-point selection. The held-out test data is reserved for the final generalisation evaluation.

## 11. Computational Performance

Computational measurements include parameter count, model storage, inference latency, approximate FPS and peak GPU allocation when CUDA is available.

Notebook 07's verified execution used a CPU runtime. Its CPU latency results should not be directly compared with the GPU inference results from earlier notebooks.

Computational performance depends on hardware, package versions, preprocessing and postprocessing settings.

## 15. Limitations

- Class imbalance, especially for rare defect categories.
- Limited independent images representing some defect types.
- Small held-out test split.
- Reliance on existing annotation quality.
- Sensitivity to confidence thresholds.
- Hardware and software dependence of inference measurements.
- Possible differences between reproduced and original trained checkpoints.

The repository provides source code, analysis notebooks, tests and reproduction procedures. Datasets and trained checkpoints must be obtained separately.
